# Kalbub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Kalbub — an offline-first Android APK (Expo/React Native) that helps Bububb log her menstrual cycle, predict the next period, and receive local reminders.

**Architecture:** Single-user, on-device app. `expo-sqlite` holds period ranges and daily logs; a pure-TypeScript prediction module computes averages, next-period prediction, fertile window; `expo-notifications` schedules local reminders from the prediction; file-based routing via `expo-router` with 4 tabs (Kalender · Catat · Statistik · Atur) plus an onboarding gate. No backend, no analytics, no login.

**Tech Stack:** Expo (latest stable SDK), React Native, TypeScript, expo-router, expo-sqlite, expo-notifications, jest-expo for unit tests of logic. Build/distribute via EAS Build (APK) + EAS Update (OTA).

**Spec:** `docs/superpowers/specs/2026-11-13-kalbub-design.md`

## Global Constraints

- Bahasa Indonesia UI; copy tone hangat & personal, bukan klinis.
- App name tampil: **Kalbub**; package `com.kalbub.app`; greeting "Hai, Bububb".
- Colors: dasar krem/rose (Soft Floral) + aksen `#FFD23F` dan `#FF5D8F`; border neo-brutalist tidak dipakai.
- Platform Android saja; target API 26+; offline-first; semua fitur jalan tanpa internet.
- Tanpa backend, tanpa analytics/telemetry, tanpa login, tanpa kunci PIN/biometrik.
- Data hanya di perangkat; `android.allowBackup` harus `false`.
- Distribusi APK via EAS Build; pembaruan JS/aset via EAS Update (`expo-updates` dikonfigurasi sejak hari pertama).
- Hari haid disimpan sebagai **rentang mulai–selesai**, bukan flag harian.
- Default siklus 28 hari / durasi haid 5 hari sebelum ada data.
- Notifikasi: H-2 dan hari-H prediksi, default 09:00, boleh menampilkan isi asli (lock screen normal).
- Prediksi lewat tanpa catatan → kartu beranda "Sudah datang, Bububb?" (ya → geser & jadwalkan ulang; belum → tampilkan "terlambat X hari").
- Jangan minta izin notifikasi berlebihan di awal; channel Android 8+ diperlukan.

## Review Focus

Kegagalan yang paling mungkin menggigit pengguna (diuji di task yang memiliki kodenya):

1. **Input rentang tidak valid** (tanggal selesai sebelum mulai / rentang bertumpuk) — app harus menolak/merge, bukan menyimpan data rusak. → Task 3.
2. **Prediksi lewat tanpa konfirmasi** — notifikasi H-2/hari-H tidak boleh terkirim ulang untuk siklus yang sudah lewat. → Task 5.
3. **Perubahan data tidak menjadwalkan ulang notifikasi** — setiap add/edit/delete periode atau konfirmasi "sudah datang" wajib membatalkan & menjadwalkan ulang notifikasi. → Task 5.
4. **Perhitungan tanggal lintas zona waktu/DST** — semua tanggal disimpan sebagai string lokal `YYYY-MM-DD`, tidak pernah `new Date(str)` mentah untuk logika hari. → Task 2, Task 3.
5. **Statistik dengan data kosong/satu siklus** — layar statistik harus tampil rapi dengan 0 atau 1 siklus (tidak NaN/crash). → Task 6.
